= Setting up Phantom Metal Taste
:toc:
:toclevels: 2

This is the manual setup route for the *implemented* Rust, Julia, and Bun tools.
The repository does not currently provide an HTTP service, data loader, or
working database integration; the conceptual design documents are not an
application runbook.

The same steps are available through `./launcher.sh --setup` and `just setup`.
The launcher needs mise; `just setup` needs `just` and mise.

[horizontal]
Repository:: https://github.com/hyperpolymath/phantom-metal-taste
Kind:: Experimental mixed-language library (`rust julia bun`)
Project configuration:: `Cargo.toml`, `Project.toml`, `package.json`, `site.json`
Toolchain configuration:: `mise.toml`; `manifest.scm` and `channels.scm` for Guix

== 1. Prerequisites

Install Git, mise, and a system C toolchain. On Windows, use WSL2.

[cols="1,2,3"]
|===
|Tool |Why |Install

|Git
|Clone the repository and inspect changes
|Fedora `sudo dnf install git` · Debian/Ubuntu `sudo apt install git` · macOS `xcode-select --install` · Windows `winget install Git.Git`

|mise
|Install the Rust, Julia, Bun, Just, and ShellCheck tools declared by this project
|macOS `brew install mise` · Fedora `sudo dnf copr enable jdxcode/mise && sudo dnf install mise` · Windows `winget install jdx.mise` · other systems: https://mise.jdx.dev/installing-mise.html

|C compiler and pkg-config
|Native build support for Rust and Julia dependencies
|Fedora `sudo dnf install gcc pkgconf-pkg-config` · Debian/Ubuntu `sudo apt install build-essential pkg-config` · macOS install Xcode Command Line Tools

|OpenSSL command (optional)
|Generate local-only database passwords if using `compose.yml`
|Fedora `sudo dnf install openssl` · Debian/Ubuntu `sudo apt install openssl` · macOS normally includes `openssl` through Homebrew
|===

On macOS, the generated estate launcher uses GNU `readlink -f`. Install
Homebrew coreutils and put its GNU-compatible commands first on `PATH` before
running the launcher:

[source,bash]
----
brew install coreutils
export PATH="$(brew --prefix coreutils)/libexec/gnubin:$PATH"
----

The launcher is generated from the binding RSR template; do not patch the
vendored launcher by hand. This portability requirement should be removed when
the canonical template fixes its macOS path resolution.

If installing mise with its standalone installer, download it, inspect it, and
then run it. Do not pipe an unreviewed download into a shell. Add the activation
line printed by the installer to your shell and open a new shell.

== 2. Get the repository

[source,bash]
----
git clone https://github.com/hyperpolymath/phantom-metal-taste.git
cd phantom-metal-taste
----

A complete GitHub source archive can be extracted instead of cloning. Preserve
its hidden tracked files, especially `.well-known/` and `.github/`. The normal
build and test commands use the checked-in manifests and do not require Git
history; `just doctor` still requires the Git executable as a declared system
prerequisite.

== 3. Install tools and project dependencies

[source,bash]
----
mise trust
mise install
./launcher.sh --setup
----

`./launcher.sh --setup` installs `just` if needed, installs the declared mise
tools, fetches Cargo and Julia dependencies, and runs the environment doctor.
If `just` is already available, use `just setup` instead.

The tracked `mise.toml` declares tools at `latest`. The provisioning standard
requires a generated `mise.lock` with checksums for those tools. *The lock has
not yet been generated in this checkout*: the current sandbox cannot access
mise's upstream Julia version metadata endpoint. Until that lock is generated
and committed, first-time setup resolves current releases and requires network
access. Do not treat the toolchain as checksum-locked yet.

== 4. Build, test, and use the code

[source,bash]
----
just build          # Rust workspace, Julia precompile, and allowlisted site build
just test           # Rust unit tests, Julia package tests, and Bun tests
just lint           # Rust Clippy checks
just fmt-check      # Rust formatting check
just site-check     # two site builds compared byte-for-byte
just demo           # deterministic Julia analysis example
just validate       # doctor + lint/format/test/site-reproducibility gates
----

`just wasm-build` is optional and requires `rustup` with the `wasm32-unknown-unknown`
target. `just run` explicitly reports that no application entry point exists.
The demo uses library functions directly; it does not require a server or a
running database.

== 5. Optional database containers

ArangoDB and Virtuoso are optional infrastructure examples. They are not
required by the Rust or Julia packages and no current source code connects to
them. The compose file requires unique local passwords and binds service ports
to loopback:

[source,bash]
----
export ARANGO_ROOT_PASSWORD="$(openssl rand -base64 32)"
export VIRTUOSO_DBA_PASSWORD="$(openssl rand -base64 32)"
just db-up
# ...when finished:
just db-down
----

Do not reuse these passwords outside the local containers or commit them to the
repository. `just db-logs` follows container logs. Remove persisted data only
through an intentional volume-removal command; the provided `db-down` preserves
it.

== 6. Guix route

With GNU Guix installed, use the pinned development shell:

[source,bash]
----
guix time-machine -C channels.scm -- shell -m manifest.scm
mise trust
mise install
just setup
----

`manifest.scm` provides Git, Bash, coreutils, Just, mise, ShellCheck, and Rust
build tools. Julia and Bun are installed by mise because the pinned Guix channel
does not provide the requested tool versions.

`guix build -f guix.scm` installs this mixed-language checkout as a *source
package*. It does not produce a service binary: no service is implemented.
`just dev-shell` enters the Guix shell when Guix is installed and otherwise uses
the mise environment.

== 7. Troubleshooting

Run `just doctor` or `./launcher.sh --doctor` and follow the fix attached to each
code. `just heal` applies only safe, reversible fixes.

[cols="1,3,3"]
|===
|Code |Meaning |Fix

|PV-E01
|Git is missing
|Install Git using the OS package manager (<<prerequisites>>).

|PV-E02
|Just is missing or older than 1.42
|Install it with mise: `mise use -g just@latest`.

|PV-E03 / PV-E10
|A declared tool or language binary is missing
|Run `mise install` and then `just doctor` again.

|PV-E11
|A system dependency listed in the provisioning deed is missing
|Install the named OS package and repeat `just doctor`.

|PV-E20
|`mise.toml` is missing
|Restore it from version control.

|PV-E27
|The launcher is not executable
|Run `chmod +x launcher.sh`.

|PV-E40
|Neither Guix nor mise is available for a development shell
|Install mise, or install Guix and use `manifest.scm`.

|PV-E50 / PV-E51
|A repository-specific doctor check or script failed
|Read the preceding output and fix the named local check.

|PV-W01
|mise is not installed
|Install mise; otherwise the launcher can only show its manual setup guidance.

|PV-W20
|`mise.lock` is missing
|On a machine with access to mise's metadata endpoints, run `just toolchain-refresh`, review the generated checksums, and commit the lock. Do not hand-write it.

|PV-W23
|A mise config declares a prohibited tool/backend
|Remove the offending declaration and rerun `just doctor`.

|PV-W24–PV-W29
|A provisioning file is missing or still contains template placeholders
|Compare the file with the provisioning standard and fill only repository-specific facts.
|===

If setup still fails, capture `just doctor > doctor.txt 2>&1` and attach that
output to an issue. Never include credentials or password values.
